## Question

Move the sync crypto from per-device DEKs to a single **group key K**, so any
trusted device can read any shared identity record (the precondition for
GS2–GS5). Define K's lifecycle, its per-device wraps, the record envelope, the
mirror migration, and the one-time join-secret primitive.

## Current model (to replace under this ticket is the *sync* layer only)

- Per-device DEK; records encrypted under the writer's DEK
  (`encodeIdentityRecord(dek, …)`, `reencryptUnderDekB`, `adoptHostCode` in
  `src/lib/sync/records.ts`); envelope = device DEK wrapped under the recovery
  code + passkey (`types.ts` `DeviceEnvelope`).
- The recovery code currently doubles as "the universal unwrap."
- Vault-unlock machinery (`vault/crypto-dek.ts`, `passkey.ts`, `service.ts`)
  stays as the *local* key-wrap layer — only the sync-layer key becomes K.

## Design sketch

- **K** = fresh 32-byte AES key, generated by the host on first invitation.
- **Per-device wrap of K**: reuse the existing `wrapDekUnder` shape — each
  device stores `K` wrapped under (a) its passkey PRF and (b) its own
  per-device passphrase/recovery string. Envelope schema gets a distinguished
  record for the group key (`method: 'group'` or a `group` block). Local
  unlock = unwrap K with the device's passkey/passphrase.
- **Records**: encrypt identity JSON under K (drop the per-writer DEK).
  `writer` stays for provenance. Tombstones unchanged.
- **Join secret**: a random secret S (e.g. 32 bytes); the invitation carries a
  derivation (see GS2) that lets the joiner recover K for the one join.
  Host keeps S's validity bound to one recipient; rotation primitive so a
  consumed invitation cannot be reused.

## Acceptance

- Schema + codec updated: records-under-K, envelope groups K + per-device
  wraps; codec tests updated/green.
- `encodeIdentityRecord`/read path work under K; legacy (per-writer DEK)
  records still readable on a one-time migration.
- A unit test reads a record with a *different* device's local unwrap producing
  the same K (i.e. cross-device read works with no recovery-code exchange).
- The join-secret primitive: derive→reveal→consume round-trip test.
