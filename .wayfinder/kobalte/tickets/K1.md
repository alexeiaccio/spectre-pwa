## Question

Replace the native `<select>` for "Auto-lock after hiding the app" (`IdentitiesScreen.tsx`) with `@kobalte/core/select`. This is the smallest, lowest-risk form control and pins the alpha's collection-based Select API for the rest of the adoption.

## What to pin (alpha API is collection-based, differs from Kobalte 0.13)

- **`Select.Root` options shape**: `options={[...CollectionNode]}` — confirm the exact node shape (`{ value, label }` vs richer), how `defaultValue`/`onChange` map to the signal-backed `prefs().autoLockMinutes`.
- **Selection render**: how `Select.Value` exposes the selected node (render-prop? `state.selectedOption()`?) to show "5 minutes".
- **Styling hooks**: the `data-*` attributes Kobalte sets (open/selected/disabled) and how to map them to the existing Tailwind B/W classes via `@kobalte/tailwind` or plain `data-*` selectors — the repo has no `@kobalte/tailwind` yet; decide add-vs-handroll.
- **Touch/keyboard on small screen**: confirm the alpha popover behaves on tap + arrow keys, which is the whole reason to adopt it.

## Resolution (2026-08-14) — **blocked: alpha Select open is broken under Solid 2 rc.0 strict mode**

Replaced the native auto-lock `<select>` with Kobalte Select in `IdentitiesScreen.tsx` (`@kobalte/core/select`). The API is now pinned:

- **Import**: per-component named exports from the subpath (`Root/Trigger/Value/Portal/Content/Listbox/Item/ItemLabel`). The root barrel `@kobalte/core` does NOT resolve under `moduleResolution: bundler` (exports map has `./*`, no `.`).
- **Option shape**: plain objects; `options` array + `optionValue`/`optionTextValue` key names; `value`/`defaultValue`/`onChange` are **scalar** in single-select (array forces the `multiple` overload — a TS trap).
- **Value render**: `Select.Value` render prop exposes `state.selectedOption()` returning the **raw option object** (not a CollectionNode); `Item`'s `itemComponent` gives `item.rawValue` = the option.
- **Styling**: Kobalte sets `data-[highlighted]`/`data-[selected]`/`data-[open]`; plain Tailwind `data-*` selectors work without `@kobalte/tailwind`.

**Renders, but does not open.** The trigger + selected value render correctly (shows "5 minutes", theme-correct), but clicking the trigger leaves `aria-expanded="false"` — the listbox/options never mount. Every render also emits 4 `STRICT_READ_UNTRACKED` warnings from inside Kobalte's own `ButtonRoot` (the Solid 2 strict-mode flagging pre-RC internals).

**Decision: hold Kobalte adoption.** The open toggle is broken and the library emits strict-mode warnings in its own core. Both are library-side issues we cannot patch from the app, and K2/K3/K4 all depend on interactive components. Revert K1 to the native `<select>` (the previous code is correct and verified). Revisit when `@kobalte/core` alpha ships a Solid-2-rc-clean release; re-run this ticket as the first test. Hand-rolled headless Select remains the fallback if the alpha doesn't mature.

## Acceptance (result)
