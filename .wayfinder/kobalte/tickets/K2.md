## Question

Replace the native `<select>` elements in the shared `SiteFields` (purpose: password/login/answer; template: Long/Maximum/…/Phrase) with Kobalte Select, reusing the API pinned in K1.

## Notes

- Two selects sit side-by-side in one row; changing purpose auto-bumps the template (`purpose === 'login' ? 30 : purpose === 'answer' ? 31 : 17`).
- Both are controlled by `SiteFormState` (`newSite`/`editDraft` signals). Kobalte `onChange` maps to the existing `setDraft` updaters.
- The B/W theme's compact `text-sm` select row must not overflow the small screen — popover width/placement constraints.

## Acceptance

- Purpose + template selects use Kobalte Select, match `SiteFields` styling, preserve the purpose→template auto-bump.
- Add-site and edit-site forms both still work (derive/edit/delete paths unaffected).
