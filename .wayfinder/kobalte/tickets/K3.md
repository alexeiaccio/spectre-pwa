## Question

Adopt `@kobalte/core/text-field` for the app's text inputs: site name, security answer (SiteFields), full name + passphrase (IdentitiesScreen add-identity), recovery code (LockedScreen/SetupScreen), passphrase (IdentityScreen unlock).

## Notes

- Rationale is consistency + the `tap` (≥44px) touch target and B/W theme, not new behavior — native `<input>` mostly works, but TextField gives label/description/error wiring and consistent `data-*` states.
- `type="password"` must be preserved on passphrase/recovery inputs (Kobalte TextField passes through native input attrs).
- Keep the existing `value`/`onInput` signal wiring; do not change optimistic flows.
- **Pivot (2026-08-14):** TextField does NOT use the popover/disclosure machinery that broke Select (K1), so it is adoptable now. Start with the site-name input in `SiteFields`, then the security answer, then identity/passphrase/recovery inputs. Select (K2) stays blocked until the alpha's popover is fixed.

## Acceptance

- All listed inputs render via Kobalte TextField with identical styling; passphrase fields still mask text.
- No change to vault/unlock/session behavior.
