## Question

Replace the native `<input type="number">` "Spectre counter" (SiteFields add/edit) with `@kobalte/core/number-field`.

## Notes

- Counter is `min 1`, integer, currently clamped via `Math.max(1, Number(...))` in the `onInput` handler. NumberField gives stepper + keyboard + the same clamp semantics; confirm how `onChange`/`value` map to `SiteFormState.counter`.
- On a tiny screen, the stepper buttons must stay within the `w-16` compact row.

## Acceptance

- Counter edits (add + edit) work through NumberField, still clamped ≥1, persisted via the existing optimistic `commitMutation`.
- Row layout unchanged on small screens.

## Resolution

- **Done.** `SiteFields` add/edit forms use a shared Kobalte `NumberField` (`src/components/ui/NumberField.tsx`, committed in `ae9fabe` "feat(ui): Kobalte-based design system") wired as `value={draft.counter}` / `minValue={1}` / `onChange` clamping `Math.max(1, v)`.
- Counter edits flow through the existing optimistic `commitMutation`; the input stays inside the `w-16` compact row.
- Verified in the K1–K4 session (map.md): counter → row `#N` propagates; NumberField's `STRICT_READ_UNTRACKED` warnings are cosmetic (value still flows), unlike Select's earlier broken open.
